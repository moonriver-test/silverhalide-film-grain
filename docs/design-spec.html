01一句话定义与交付边界

银盐是一个 Photoshop 面板插件：你选一卷胶片、拨三个滑块，它按真实胶片的物理规律在你照片的中灰调里长出颗粒——放大看会成团，缩小时会消失，和你换一卷真胶片拍出来一样。

这个 demo 要证明什么

  1. 视觉上像不像。把输出和真实胶片扫描件放一起，有胶片经验的人分不出来。这是 demo 的第一目标。
  2. 交互上顺不顺手。不懂物理的摄影师能不能在 30 秒内调出满意的结果；懂的人能不能找到他要的所有参数。
  3. 架构上撑不撑得住。「颗粒场与幅度解耦」这个架构决策能否让拖动滑块做到准实时。这一条如果验证失败，整个性能路线要重做。

这个 demo 不做什么

  • 不追求全分辨率实时预览（接受松手后 1–3 秒的精算延迟）
  • 不做多线程/GPU 优化（先用最简单的串行实现跑通正确性）
  • 不做色调曲线、halation、色彩耦合——颗粒之外的「胶片感」因素全部留给后续阶段
  • 不做预设的实测标定（先用报告里的公开数据 + 视觉微调，标定是 P2 的工作）

02产品定位与命名

表 1　定位与命名决策
维度决策理由
产品名 银盐 / Silver Halide（内部代号 silverhalide） 「银盐」是胶片成像的化学本质，专业用户一看就懂，且与所有竞品（FilmConvert、Dehancer、LiveGrain）在命名上区分开——那些名字都在讲「效果」，我们讲「原理」。
目标用户 有两类，界面必须同时服务 ① 摄影师：不懂也不想知道 p(1−p)，只想选个 Portra 400 然后拖一下强度。② 调色师 / 技术型用户：会追问「为什么高光没有颗粒」，需要看到曲线和物理参数。
核心差异点 唯一的「按观看条件正确缩放」的颗粒插件 报告 §4.6：放大率是颗粒感的第一主导变量（PGI 28→79），比胶片型号差异更大。所有竞品都把颗粒当成固定像素尺寸的素材层，只有我们从物理上做对了这一条。
文案红线 禁用「噪声」「Noise」二字 报告 §5.7 与 §7.4：这两个词会把用户拉进数码噪声的心理模型，导致调参方向系统性错误。统一用「颗粒 / Grain」「颗粒度 / Granularity」「团簇 / Clumping」。

03技术选型：UXP 面板还是 C++ 智能滤镜

这是整个项目最关键的一次性决策，因为两条路线的代码几乎不共享。先把两条路的物理约束摊开：

表 2　两条技术路线对研究报告六条硬约束的满足度
研究报告的硬约束UXP 面板（JS/WASM）C++ Plug-in SDK 智能滤镜

性能（拖动滑块准实时） 高风险 大图 getPixels/putPixels 往返是主要瓶颈 可控 原生 + 可上 GPU（CUDA/Metal）
开发迭代速度（对 demo 最重要） 快 HTML/CSS/JS，改完即见，无需编译，无需 SDK 环境 慢 C++ 编译、SDK 版本匹配、调试靠日志
签名/分发门槛 低 可本地加载；上架 Creative Cloud 需审核 高 传统插件需 ZXP 打包与签名

决策：两段式，算法核心从第一天就与壳层解耦

  • Demo v0.1 用 UXP 面板。目标是验证「颗粒长相」与「交互模型」，不是验证性能。UXP 能把迭代周期压缩到小时级，这对 demo 阶段价值极高。
  • 算法核心写成平台无关的纯函数模块（TypeScript，零 DOM / 零 PS API 依赖，输入输出都是 Float32Array）。这一个决定让后续迁移只需重写「读像素/写像素」和「面板 UI」两块，核心算法一行不改。
  • 产品化阶段换 C++ 智能滤镜，把同一套算法用 C++ 重写（或把 TS 核心编译成原生），拿到位深、线性域、GPU、非破坏四项原生能力。迁移的触发条件见 §10 决策门槛。
选型的第一个不确定项——必须先做 30 分钟可行性实验

UXP 的 imaging.getPixels / putPixels 在大图 16 位上的实际吞吐，以及 UXP 运行时对 WebAssembly 与 Web Worker 的支持程度，是我目前无法从文档确证的。这两点直接决定 demo 的性能天花板。

实验内容（写代码之前先做）：读入一张 6000×4000 的 16 位图像，不做任何算法，直接 getPixels → 原样 putPixels，测量一次往返耗时；再测一次 1024×1024 的分块往返，测 Worker 能否正常创建。

判据：若全图往返 > 1.5 s 且 分块方案也不可行，则 demo 直接改走 C++ SDK 路线，不要浪费时间在 UXP 上。

04交互设计

4.1 面板整体结构

4.2 六个区块逐个说明

① 胶片（预设）

  • 按族分组：黑白 / 彩色负片 / 彩色反转。分族不是分类癖，而是物理需要——报告 §3.4 指出彩色染料云的尺度是黑白银团的 2–5 倍且更柔，两组预设必须使用不同的半径与柔化参数。
  • 每个预设配一张真实胶片扫描缩略图（不是渲染图）。这一条很重要：用户在扫过预设时，靠的是视觉记忆匹配，不是参数名。没有缩略图的预设列表等于让人盲选。
  • 首批预设（对应用户已有的审美认知，也对应报告里有公开数据的型号）：
    族预设数据依据
    黑白Tri-X 400 / HP5 Plus / T-Max 100 / Delta 3200报告未采集黑白实测，先用视觉标定，标为「待标定」状态
    彩色负片Portra 160 / Portra 400 / Ektar 100 / Pro Image 100柯达技术资料有 PGI 数值（报告表 6），可作为强度锚点
    彩色负片（电影）VISION3 500T报告图 2 的完整三通道颗粒度曲线，数据最扎实，作为默认预设
    彩色反转Velvia 50 / Ektachrome E100报告未采集；已知反转片颗粒感整体强于负片（约 ×2.5）
  • 预设列表要能显示「实测标定」还是「估计值」标签。诚实标注比假装精确更重要——报告 §8.2 明确说了公开数据不足。

② 颗粒（三个核心滑块）

这里做了三个不寻常的设计决策：

决策 A：强度单位用 PGI，不用百分比

滑块右侧不只是数字，而是一句人话状态：PGI 18 · 低于可见阈值 / PGI 32 · 轻微可见 / PGI 55 · 明显 / PGI 80 · 强烈。

依据：报告 §4.6 的 PGI 定义——25 是视觉阈值，每 4 个单位是一个 JND。这给了滑块物理量纲和心理量纲，用户能理解「32 和 36 的差别刚好能看出来」「18 是白调了」。百分比滑块给不了这种语义。

决策 B：尺寸滑块用「画幅」表达，内部换算成放大率

用户看到的是「辅助提示 + 一个连续滑块」，滑块左端对应 Super 8（颗粒最粗），右端对应 4×5 页片（最细），中间标出 16mm / 135 / 120 的位置。内部换算为等效放大率。

依据：报告 §4.6 表 6——同一底片的 PGI 随放大率从 4.4× 到 17.8× 变化时从 28 升到 79。放大率是主导变量，但用户脑子里没有「放大率」，只有「画幅」。用用户的语汇承载物理参数，这是整个交互设计的核心手法。

决策 C：强度与尺寸在内部部分耦合，但界面上看起来是独立的

报告 §4.2 的 Selwyn + √D 律表明：改变颗粒半径会同时改变每个分辨单元内的颗粒数 N，从而按 √N 影响 σ。物理上二者不独立。

处理方式：界面上仍是两个滑块（用户认知负担最低），但内部施加一个物理修正项——用户增大颗粒尺寸时，强度曲线整体做一次轻微上修（约 ×√N 的偏离），使结果符合物理而不是机械独立。修正量的幅度需要实测标定，demo 阶段先用理论值。

这条必须写进 tooltip，否则专业用户会觉得「我明明没动强度，怎么变了」。

③ 色调响应

  • 可编辑曲线：横轴是图像亮度（0–100%），纵轴是颗粒强度系数（0–150%）。默认曲线两端锁死在 0——这不是设计偷懒，是报告 §4.7 的硬结论：纯黑没有颗粒（没有晶体被曝光）、纯白没有颗粒（覆盖率饱和）。
  • 默认峰值在 55–65% 灰，依据是布尔模型的 p(1−p) 与 PICS 的打印体颗粒度峰值（D ≈ 0.75）。
  • 曲线下方铺一条灰阶梯度条，把曲线的高度直接画成各亮度处的颗粒浓度。用户改曲线时能立刻看到「我要在哪一段加颗粒」，比看数字直观得多。
  • 三个快捷按钮覆盖 90% 的使用场景：「胶片」（默认物理曲线）/「暗部保护」（峰值右移、暗部压得更狠，适合人像）/「全色调均匀」（接近水平直线，用于风格化）。

④ 色彩

  • 亮度 / 色度比：单个双极滑块，默认 80 / 20。依据报告表 8。当色度分量超过 35% 时，滑块下方弹出警示：「色度颗粒偏高，可能出现彩虹噪点」。用警告代替硬限制——有经验的用户可能就要这个效果。
  • 三通道权重：三个可点击的色块，默认 R .36 / G .40 / B 1.00，来自报告图 2 的 VISION3 实测比值。色块面积正比于权重，不用看数字就能发现「蓝通道最大」这个事实。
  • 单色颗粒开关：勾选后三通道共用同一颗粒场，得到中性灰颗粒 = 黑白胶片模式。这同时是「三通道独立 vs 同步」的教学开关——用户来回切换几次就理解什么是色度颗粒了。

⑤ 观察条件 核心差异点

这一块是整个插件唯一无法被现有产品替代的部分，也是报告 §4.6 的直接产物。

表 3　观察条件区块的交互内容

⑥ 高级（默认折叠）

颗粒半径分布（μᵣ / σᵣ）
对数正态分布的均值与离散度。μᵣ 控制颗粒绝对大小，σᵣ 控制「大小混杂」的程度。σᵣ 调大 → 大小颗粒混合 → 更接近真实乳剂（真实胶片从来不是单分散的）。默认值取自报告表 2、表 3 的尺寸区间。
观察侧柔化（σ_view）
对应布尔模型里那个模拟「放大 + 人眼」的高斯核 φ。这是唯一一个纯粹为了「像扫描件」而存在的参数——调大会让颗粒变软、变糊，模拟低端扫描仪或远距离观看。专业用户会喜欢这个。
图像柔化联动（0–100%）
依据报告 §5.5 的铁律「颗粒是画面最锐利的元素」。这个滑块按真实胶片的 MTF 关系轻微柔化底层图像，让颗粒相对更锐利。默认给一个很小的值（约 15%）。这是最反直觉、但最能提升「胶片感」的一个参数。
随机种子 + 随机化按钮
依据报告 §5.6。批量处理组图时，逐张换种子才不会出现「所有照片颗粒位置相同」的破绽。UI 上给一个「应用到本组所有图像时随机化」的选项。

4.3 三个关键交互机制

机制一：1:1 对比窗口 解决「小视图看不见」的问题

这是必须解决的体验问题。报告 §4.6 指出颗粒感随放大率急剧变化——所以当用户把画布缩到 25% 时，颗粒在物理上就应该是看不见的（PGI 掉到阈值以下）。用户会立刻以为插件坏了。

方案：面板内嵌一个始终 1:1 的取样窗口

  • 面板顶部固定一个约 200×140 px 的小窗，永远显示图像某处的 100% 裁切，左半原始、右半处理后，中间可拖动分割线。
  • 取样点通过「在画布上点一下」或小窗内拖动来指定，小窗角落显示坐标。
  • 这样无论画布缩放到多少，用户始终有一个可信的 1:1 参照——这是所有专业颗粒插件的刚需。

机制二：颗粒场与幅度解耦 决定实时性成败

这是架构决策，但它直接决定交互手感，所以放在交互章节讲。

把「呈现」拆成两层 颗粒场 G(x, y)　← 只依赖：随机种子、颗粒半径、团簇度、观察侧柔化
　　（贵：需要生成 + 相关滤波。参数量级：全图级）

幅度 A(u)　← 只依赖：预设、强度、色调曲线、色彩配比、通道权重
　　（便宜：一张 1024 点的查找表。参数量级：常量）

输出 = 图像 + G(x, y) × A(u(x, y)) × 通道权重
这个拆分带来的直接体验
  • 拖动强度滑块、编辑色调曲线、改色彩配比 → 颗粒场完全不动，只需重算一张 LUT 再做逐像素乘加 → 准实时，无延迟感
  • 拖动尺寸或团簇度滑块 → 颗粒场必须重算 → 交互中先降采样预览（见机制三），松手后精算

如果架构不做这个拆分，那么每拖一次强度滑块都要重算整幅颗粒场，实时性直接死掉。这是必须在第一天就定下来的设计。

真实预览（默认）

按当前画布缩放级别渲染等效观看条件。物理正确：缩小画布 → 颗粒消失；放大到 100% → 颗粒清晰。

5.3 L1 物理预计算层

这一层是整个插件「物理正确」的唯一来源。它的输入是用户的滑块，输出是后续两层需要的全部数值。

步骤 1：把用户参数翻译成物理量

像素 ↔ 微米的换算（必须先建立这个约定） 假设：把输入照片视为「等效 135 全画幅」（感光区宽 36 mm）铺满图像宽度 W px
1 px = 36 / W mm　⇒　r_px = r_μm × W / 36000

例：W = 6000 px → 6 μm/px。报告 §5.1 的「颗粒簇 10–30 μm」⇒ 1.7–5.0 px。
这个结果与报告给出的经验值（2–5 px）吻合，说明这个约定是合理的，可以作为默认标定基准。
表 7　L1 输出的四个物理参数及其来源
参数含义由什么决定
μᵣ颗粒平均半径（像素）预设的颗粒绝对尺寸 × 「画幅」滑块的等效放大率 ÷ 观察条件缩放。三个来源相乘——这正是报告 §4.6「放大率主导」的落地。

步骤 2：计算归一化幅度曲线 a(u)

目标：得到「图像亮度 u → 颗粒相对幅度」的曲线。这是报告 §4.7 三条事实的交汇点。

Demo 阶段：解析近似（先跑通）

a(u) = 2·√( p(1−p) )，　p = uγ，　γ = ln(0.5)/ln(uPeak)
直接来自布尔模型的覆盖波动方差 Var = p(1−p)（报告 §4.7 事实 C）。
形态：中间调峰值、两端为零。一条式子命中报告的核心结论。

优点是零成本、无需蒙特卡洛、行为可预测。缺点是忽略了 μᵣ 与 σ_view 对曲线形状的影响（颗粒很小时曲线更窄，颗粒很大时更平）。对 demo 而言足够。

P1 阶段：蒙特卡洛标定（提升精度）

  1. 取 17 个采样灰度 u ∈ {0, 1/16, 2/16, …, 1}；
  2. 对每个 u，在 256×256 窗口内生成布尔模型实现：圆盘中心数 = λ(u)·Awin（λ 由报告 §6.5 公式③ log(1/(1−u))/E[πr²] 给出），半径按对数正态采样；
  3. 与高斯核 φ(σview) 卷积；
  4. 统计窗口内方差 → Var(u)；
  5. 归一化 a(u) = √Var(u) / √Varmax，用单调三次样条插值成 1024 点 LUT。
这一层是「物理模型」与「实时渲染」之间的桥。预计算的本质是：把昂贵的蒙特卡洛模拟从「每帧执行」降级为「参数变化时执行一次」。原论文的实现在典型工作负载下开销较大，而我们的架构里它根本不参与交互循环。

步骤 3：生成相关核 K 已按实现修正

目标：一个能让白噪声变成「带限 + 团簇」的滤波器。注意：频谱目标不是带通而是低通带限（见文档顶部勘误）。

方案：单高斯低通 + 乘性对数正态调制 细颗粒：　F = G(σ_g) ∗ W　　　　σ_g = μᵣ / 2
团簇：　　G = F · exp( β · C ) / exp(β²)　　C = G(σ_c) ∗ W′，独立噪声流
σ_c = μᵣ · (2 + 4c)　　β = 0.9 · c

归一化解析精确（W、W′ 均为零均值单位方差、且核按 L2 归一化）：
  E[G]　 = E[F]·E[e^{βC}] / e^{β²} = 0
  Var(G) = E[F²]·E[e^{2βC}] / e^{2β²} = e^{2β²}/e^{2β²} = 1
与像素位置无关，因此分块不会产生强度台阶。
原方案（高斯差分 DoG）为什么被推翻

设计稿原本写 K = G(σ₁) − k·G(σ₂)，理由当时是「报告 §4.4 要求带通」。实现阶段的实测推翻了它：

  • DoG 的功率谱峰值落在远低于颗粒尺度的频率上——实测周期约 96 px，而颗粒直径只有 4 px。用它做出来的不是颗粒，是大尺度云斑。
  • 原公式 σ₂ = σ₁(1 + 4c) 在 c = 0 时给出 σ₂ = σ₁，DoG 退化为零核，颗粒直接消失。这是一个公式级的 bug。
  • 更要紧的是：颗粒的频谱本来就不是带通（Selwyn 定律 σ·√a = 常数 ⟺ 低频功率谱平坦），所以「用 DoG 造带通」这个目标本身就建立在错误前提上。

换成乘性调制之后还多了一个好处：「团簇」在物理上本来就是颗粒密度的空间不均，而不是某个尺度的带通滤波结果。乘性对数正态调制直接建模这件事，参数 c 的含义（密度起伏的强度）也比原来的「低频成分权重」清晰得多。

为什么用可分离高斯而不是 FFT 频域滤波
  1. 可分离、复杂度低：二维卷积退化为两次一维卷积，代价 O(N·k) 而非 O(N log N)。
  2. halo 好算：核的有效半径是 3σ，halo 宽度直接由它决定，不用考虑频域绕回（wrap-around）这种容易出错的细节。
  3. 归一化有闭式解：核按 L2 归一到 1，则二维可分离卷积输出的方差精确等于输入方差（1），无需任何样本估计。
  4. 参数可解释：σ_g 对应「颗粒多细」，σ_c 对应「团簇多大」，β 对应「密度起伏多强」。

5.4 L2 噪声合成层

① 坐标寻址的确定性哈希 PRNG 关键实现细节

为什么不能用普通的顺序随机数发生器 需求：分块并行处理时，任意像素 (i, j) 的噪声值必须只由 (种子, 坐标, 流编号) 决定。

hash(seed, stream, i, j) → uint64 → [0, 1)　（SplitMix64 类混合函数）

若用顺序 PRNG（如 Math.random 或线性同余）：
① 块的处理顺序会影响结果 → 拖动滑块时颗粒会「跳动」；
② halo 区域无法独立重算 → 块边界颗粒断裂。

流编号的分配：stream 0 = 亮度场，stream 1/2/3 = 色度 R/G/B。这样同一坐标的亮度与色度噪声互相独立，同时各自可复现。

② 白噪声 → 相关噪声

  • 在 (512 + 2h)² 的缓冲上生成白噪声（h = halo 宽度 ≥ ceil(3σ₂)）。
  • 做可分离一维卷积：细颗粒场一次（σ_g），团簇场一次（σ_c），再按 §5.3 步骤 3 的乘性公式合成。
  • 归一化必须用理论方差，不能用实际样本方差。
这是一个很容易踩的坑

如果对每个 tile 用「该 tile 内噪声的实际标准差」做归一化，那么每个 tile 的方差估计都不同 → 相邻块之间有轻微强度台阶 → 大平面上出现可见的方块（正是报告 §7.4 反模式里的网格效应）。

正确做法：把一维高斯核归一化到单位 L2 范数（||k||₂ = 1）。二维可分离卷积的方差即精确等于输入方差（1），没有任何样本估计。这个归一化与像素位置无关，因此天然全局一致。

③ 关于噪声的分布形态（一个值得做的实验）

真实胶片颗粒的分布不是高斯——布尔模型的输出是非高斯的二值随机集的滤波结果。因此 demo 里值得做一个小实验：

  1. 用 Irwin–Hall 近似（多个均匀数求和）生成近似高斯白噪声 → 输出颗粒偏「均匀细密」
  2. 用稀疏脉冲（少量大值 + 大量零）生成重尾白噪声 → 输出颗粒更「孤立、有颗粒感」

建议把「分布形态」做成一个隐藏参数（可用于 A/B 与后续论文级标定），不放进正式 UI。

07色彩域的关键决策：曲线在感知域，注入在线性域

这是整个实现里最容易做错、也最不显眼的一步。研究报告 §8.2 已经指出「数码照片与胶片密度域没有天然映射」，本节给出一个可落地的解法。

7.1 三个域，各管一件事

表 9　三个色彩域的职责划分
域变量在本插件中的职责
感知域 v（sRGB 编码值） 定义用户编辑的色调响应曲线 A(v)。
依据：报告 §4.7 的「打印体颗粒度峰值在 D≈0.75」这个结论本身就是在带视觉权重的感知测量下得到的，所以曲线天然属于感知域。
线性光域 l（线性亮度） 实际注入颗粒的地方。
依据：只有在线性域做加减才对应「光量的增减」这一物理量。报告 §7.1 约束 12。
密度域 D = −log₁₀T 不进入我们的管线。
依据：报告 §8.2，数码图像没有天然密度对应；且若在 log 域注入噪声，暗部会被反向放大到不可控。

7.2 两个域之间的换算因子（这部分是纯推导）

推导 设 v 为目标显示值，l 为线性值，l = f(v)，工程上用 f(v) ≈ v2.2；反函数 g(l) ≈ l1/2.2。
g'(l) = (1/2.2) · l1/2.2 − 1 = (1/2.2) · l−0.5455

要让显示的颗粒幅度等于 A(v)·S：
  δv = A(v)·S·Δv₀　（我们想要的效果）
  δv = g'(l)·δl　　　（这是数学关系）
⇒ δl = A(v)·S·Δv₀ / g'(l) = A(v)·S·Δv₀ · 2.2 · l0.5455

代入 l = v2.2：　l0.5455 = (v2.2)0.5455 = v1.2

⇒ σ_lin(v) = 2.2·Δv₀ · A(v) · v1.2 · S　　⇒　σ_lin ∝ A(v) · v1.2 · S

结论就这么干净：线性域的颗粒标准差 = 用户曲线 A(v) × v 的 1.2 次方 × 强度。没有任何需要迭代或查表的复杂环节。

∝ v−1.2 常数（即线性域加等量噪声） 暗部剧烈放大、高光干净 ≡ 数码传感器噪声。这是一个一致性检验：线性域加白噪声本来就会得到「暗部最脏」的观感，公式把它复现出来了 ✓
中间调峰值
（默认 0.55–0.65）		 ∝ A(v)·v1.2 中间调最强、两端归零 胶片颗粒 ✓（报告 §4.7 表 7）
这个检验为什么重要

第二行说明这套公式能够自然复现「数码噪声为什么在暗部最脏」这一已知事实——这强烈支持了整个域划分的正确性。如果公式推出来是反的（比如线性域加噪声反而得到高光最脏），那就说明域划分错了，必须回头重做。

7.4 实现上零额外开销

把 v1.2 因子直接烘进 LUT：

运行时只有一次查表 LUT[k] = A(k/1023) · (k/1023)1.2 · S_normalize　　k = 0 … 1023
逐像素：σ_lin = LUT[ v >> 6 ]　（16 位 v 右移 6 位得到 1024 级索引）

用户编辑曲线 → 重算这张 1024 点 LUT → 约 0.1 ms。这就是「拖动色调曲线准实时」的底气。
顺带解决一个实际问题：因为曲线是按每张图自身的编码亮度查表的，所以同一套参数在欠曝和过曝的照片上会得到符合各自基调的颗粒分布，不需要用户为不同曝光的照片分别调参。

8.3 缓存策略（含一个内存优化决策）

内存设计上有一个真实矛盾：全分辨率的颗粒场如果缓存起来，Float32 三通道要 288 MB，不可接受；但完全不缓存，则拖动强度滑块也要重算 1.2 s，交互体验会崩溃。

解法：双精度颗粒场

  • 预览级颗粒场：1/2 分辨率 + Float16 + 三通道。
    内存 = 6000×4000 ÷ 4 × 2 B × 3 ≈ 36 MB。交互全程使用它，任何幅度类参数变化都在这个场上完成。
  • 精算级颗粒场：不缓存，按 tile 即时生成。
    因为精算只在松手后跑一次，1.2 s 可接受，没有必要为它付 288 MB 的代价。

这个取舍让峰值内存降到了几十 MB 量级，同时保住了交互手感——「预览用低精度缓存、精算用一次性重算」是图像处理插件的通用手法，值得作为规范写进实现。

Demo 的验收定义（什么算跑通了）

  1. 三个预设的 1:1 输出，与对应的真实胶片扫描件并排看，有胶片经验的人无法一眼分辨。
  2. 拖动强度滑块时感觉不到卡顿（< 100 ms 反馈）。
  3. 在纯色大平面（如天空）上放大 800% 检查，无重复图案、无方块接缝。
  4. 纯黑区域与纯白区域的像素值逐位不变。
  5. 诊断模式下，输出 NPS 呈低通带限，且 −3dB 截止频率与「尺寸」滑块成反比。

技术路线的决策门槛（Go / No-Go）

实验：读入 6000×4000 的 16 位图像，getPixels → 原样 putPixels，不做任何算法，测往返耗时；再测 1024×1024 分块往返与 Worker 创建。

  • 全图往返 < 800 ms，且分块可用 → Go，继续 UXP 路线。
  • 全图往返 800 ms – 1.5 s，但分块可用 → 条件 Go，只做分块方案，且接受交互预览更粗糙。
  • 全图往返 > 1.5 s，或分块 / Worker / WASM 均不可用 → No-Go，直接转 C++ Plug-in SDK 智能滤镜。UXP 只保留一个参数面板，算法全部下沉到原生。
